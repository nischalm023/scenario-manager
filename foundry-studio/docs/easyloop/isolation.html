What each control changes

Task parameterWhen trueWhat still happens
bypass_extraction
Default: false		After the order HTM physically clears its EasyLoop, the order contents disappear immediately. Boxes disappear too. There is no order-buffer detour, extraction trip, or extraction dwell.Actual picks, the loaded exit movement, and admission reservations remain. Empty reusable totes/trays return to storage normally. Empty box HTMs become available for their next assignment or the normal idle fallback.
bypass_box_induction
Default: false		A selected available empty HTM receives a box instantly at its own location. It does not visit the induction port or spend time picking up the box.The real finite HTM fleet, robot availability times, fleet headroom, travel to the assigned EasyLoop, admission, waiting, and picks remain. Tote/tray retrieval is unchanged. No HTM is teleported or created.

These controls are independent. They apply to the FulfillOrders task tree. They do not alter Cencora's task flow. Missing ports are allowed only when the corresponding stage is bypassed.

Bypassed extraction emits no extraction service cycles, so the extraction-rate metric is zero by construction. Pick counts and physical order-area entry/exit metrics still report actual simulated work. A bypass result measures the remaining system's capacity; it is not a forecast for the full workflow.

A small gain from either single bypass does not rule out that stage: another stage can mask it. The combined run exposes that interaction. When a bypass helps, trace the remaining delay before deciding whether the real workflow needs a scheduling fix, a corrected service-time assumption, or more physical capacity.

Configure the task

In a scenario with an inline composition, put the switches on its existing FulfillOrders root task:

{
  "type": "FulfillOrders",
  "after": ["LoadOrders"],
  "config": {
    "bypass_extraction": false,
    "bypass_box_induction": false
  }
}

Set either value to true for the comparison. These are JSON booleans, not quoted strings. Omission means normal behavior. When using a named composition, the same configuration belongs on its root task in the composition JSON.

The effective composition is included in the saved profile. Active switches are also printed in the startup log as [flow isolation]. Give each inspection window and exported run a label identifying its mode. Restore both switches to false for a full-workflow run.

Existing duration parameters such as extraction_secs can test service-time sensitivity without removing travel. Bypass switches remove the whole named stage; those are different experiments.

Disabling extraction increases the completed-hour pick count by 46%. Disabling box induction as well adds another 49 picks, reaching 91% of the four operators’ 1,440 single-unit picks/hour ceiling. The run with both disabled produced 310, 331, 337, and 335 picks in successive quarter-hours.

With normal extraction and box induction disabled, the scheduler stopped after 560 picks when a relay pickup could not find a route within its 300-second planning horizon. That incomplete run cannot establish the effect of disabling box induction by itself. The failure is retained for a routing/selection audit.

These are one-hour comparisons, including startup. All picked orders in the measured cohorts contained one unit. They do not yet establish long-run stability or capacity for the full multi-line order mix and putaway workload.
