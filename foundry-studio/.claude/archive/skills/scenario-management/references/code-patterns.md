# Scenario Code Patterns

## Adding a New Scenario Manager

To add a new scenario type, extend `BaseScenarioManager<T>`:

```java
package com.greyorange.dessimulator.scenarios;

import org.springframework.stereotype.Service;
import java.nio.file.Paths;

@Service
public class MyScenarioManager extends BaseScenarioManager<MyScenario> {

    public MyScenarioManager(ScenarioProperties properties) {
        super(
            Paths.get(properties.getScenariosPath(), "my-scenarios"),
            "MyScenario"
        );
    }

    @Override
    protected Class<MyScenario> getScenarioClass() {
        return MyScenario.class;
    }

    @Override
    protected String getIdPrefix() {
        return "my_";
    }

    @Override
    protected String getId(MyScenario scenario) {
        return scenario.id();
    }

    // Add create method with timestamp
    public MyScenario createScenario(MyScenario scenario) {
        var withTimestamp = new MyScenario(
            scenario.id() != null ? scenario.id() : generateNextId(),
            scenario.name(),
            scenario.description(),
            java.time.LocalDateTime.now().toString(),
            scenario.customField()
        );
        writeScenario(withTimestamp.id(), withTimestamp);
        return withTimestamp;
    }
}
```

## Adding a New Scenario Record

Add to `ScenarioModels.java`:

```java
public record MyScenario(
    String id,
    String name,
    String description,
    String createdDate,
    String customField
) {
    // Compact constructor for validation
    public MyScenario {
        if (id != null && id.isBlank()) {
            throw new IllegalArgumentException("id cannot be blank");
        }
        if (name == null || name.isBlank()) {
            throw new IllegalArgumentException("name is required");
        }
    }
}
```

## Adding a New Robot Config Type

The `RobotConfig` is a sealed interface. To add a new type:

### 1. Update SimulationConfigs.java

```java
// Add to sealed interface permits clause
@JsonTypeInfo(use = JsonTypeInfo.Id.NAME, property = "configType")
@JsonSubTypes({
    @JsonSubTypes.Type(value = RtpRobotConfig.class, name = "rtp"),
    @JsonSubTypes.Type(value = RelayRobotConfig.class, name = "relay"),
    @JsonSubTypes.Type(value = MyRobotConfig.class, name = "my-type")  // Add this
})
public sealed interface RobotConfig
    permits RtpRobotConfig, RelayRobotConfig, MyRobotConfig {  // Add MyRobotConfig
}

// Add new record
public record MyRobotConfig(
    String configType,
    int customRobotCount,
    double customSpeed
) implements RobotConfig {
    public MyRobotConfig {
        if (configType == null || !configType.equals("my-type")) {
            configType = "my-type";
        }
    }
}
```

### 2. Update InfrastructureScenario validation

```java
public InfrastructureScenario {
    // ... existing validation

    // Add handling for new robot type
    if (robotConfig instanceof MyRobotConfig myConfig) {
        // Validate my-type specific constraints
    }
}
```

## Adding API Endpoints

Add to `ScenariosController.java`:

```java
// List endpoint
@GetMapping("/my-scenarios")
public ResponseEntity<List<MyScenario>> listMyScenarios() {
    return ResponseEntity.ok(myScenarioManager.listScenarios());
}

// Get endpoint
@GetMapping("/my-scenarios/{scenarioId}")
public ResponseEntity<MyScenario> getMyScenario(@PathVariable String scenarioId) {
    return myScenarioManager.getScenario(scenarioId)
        .map(ResponseEntity::ok)
        .orElse(ResponseEntity.notFound().build());
}

// Create endpoint
@PostMapping("/my-scenarios/create")
public ResponseEntity<MyScenario> createMyScenario(@RequestBody MyScenarioConfig config) {
    var scenario = new MyScenario(
        null,  // ID generated by manager
        config.name(),
        config.description(),
        null,  // Date added by manager
        config.customField()
    );
    return ResponseEntity.ok(myScenarioManager.createScenario(scenario));
}

// Delete endpoint
@DeleteMapping("/my-scenarios/{scenarioId}")
public ResponseEntity<Void> deleteMyScenario(@PathVariable String scenarioId) {
    myScenarioManager.deleteScenario(scenarioId);
    return ResponseEntity.ok().build();
}
```

## Custom Workload Generation

Extend `ScenarioGenerator` for custom distributions:

```java
public class CustomScenarioGenerator extends ScenarioGenerator {

    public CustomScenarioGenerator(ScenarioProperties properties) {
        super(properties);
    }

    @Override
    protected void generateItemCatalog(
            Path catalogPath,
            int numSkus,
            int totalInventory,
            double popularPercentage,
            double inventoryPopularShare,
            List<String> categories) {

        // Custom distribution logic
        // e.g., exponential instead of Pareto

        try (var writer = Files.newBufferedWriter(catalogPath)) {
            writer.write("sku,name,category,weight_kg,max_inventory_quantity,ordered_quantity,is_popular\n");

            for (int i = 0; i < numSkus; i++) {
                // Generate with custom distribution
                String sku = String.format("SKU%05d", i + 1);
                String category = categories.get(i % categories.size());
                int inventory = calculateCustomInventory(i, numSkus, totalInventory);
                boolean isPopular = i < (numSkus * popularPercentage / 100);

                writer.write(String.format("%s,Product %d,%s,%.2f,%d,0,%s%n",
                    sku, i + 1, category, 0.5 + random.nextDouble(), inventory, isPopular));
            }
        }
    }
}
```

## Testing Scenarios

### Unit Test Pattern

```java
@Test
void testCreateInfrastructureScenario() {
    // Use null for PutServiceClient in tests
    PutServiceClient putServiceClient = null;

    var scenario = new InfrastructureScenario(
        "test_infra",
        "Test Infrastructure",
        "Test description",
        null,
        "rtp",
        new LayoutConfigDTO(20, 20, 1.0, null, null, null, null),
        new RtpRobotConfig("rtp", 4, 1.5),
        new OperatorConfig(12.0, 3.0, 8)
    );

    var created = infrastructureManager.createScenario(scenario);

    assertThat(created.id()).startsWith("infra_");
    assertThat(created.createdDate()).isNotNull();
}
```

### Integration Test with Real Scenarios

```java
@SpringBootTest
class ScenarioIntegrationTest {

    @Autowired
    private InfrastructureScenarioManager infraManager;

    @Test
    void testLoadDefaultScenarios() {
        var scenarios = infraManager.listScenarios();

        assertThat(scenarios)
            .extracting(InfrastructureScenario::id)
            .contains("default_rtp", "default_relay");
    }
}
```

## JSON Serialization Notes

### Jackson Polymorphic Handling

Robot configs use `@JsonTypeInfo` with `configType` as discriminator:

```java
@JsonTypeInfo(use = JsonTypeInfo.Id.NAME, property = "configType")
@JsonSubTypes({
    @JsonSubTypes.Type(value = RtpRobotConfig.class, name = "rtp"),
    @JsonSubTypes.Type(value = RelayRobotConfig.class, name = "relay")
})
public sealed interface RobotConfig permits RtpRobotConfig, RelayRobotConfig {}
```

### Handling Unknown Properties

The ObjectMapper in `BaseScenarioManager` is configured to ignore unknown properties:

```java
objectMapper.configure(DeserializationFeature.FAIL_ON_UNKNOWN_PROPERTIES, false);
```

## File Structure Conventions

```
scenarios/
├── infrastructure/
│   └── {id}/
│       └── scenario_info.json
├── workloads/
│   └── {id}/
│       ├── scenario_info.json
│       ├── item_catalog.csv
│       └── orders.csv
└── algorithms/
    └── {id}/
        └── scenario_info.json
```

- Each scenario type has its own subdirectory
- Each scenario has its own directory named by ID
- `scenario_info.json` contains the scenario metadata
- Workloads have additional CSV data files
